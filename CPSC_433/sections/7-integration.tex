\section{Integration and Comparison}
\label{sec:integration}
The OR-tree is the shared feasibility stage. The team proposes two alternatives, not a sequential three-stage pipeline.
The shared OR-tree returns a feasible $a_0$, or FAILURE if every alternative has been exhausted. The chosen optimization branch is then applied:
\[
 a_{\mathrm{out}}=\begin{cases}
 \operatorname{SetBasedImprove}(I,a_0),&\text{Proposal A},\\
 \operatorname{ANDOptimize}(I,a_0),&\text{Proposal B}.
 \end{cases}
\]
If feasibility search is interrupted without a solution, the outcome is inconclusive rather than infeasible.

Both alternatives preserve hard constraints and return a timetable with evaluation no greater than the OR-tree starting solution. Proposal A is typically less memory-intensive but can stop at a local optimum; Proposal B can prove optimality if its search completes, but has exponential worst-case work. If its resource budget expires, it returns the best feasible incumbent without claiming optimality. The two examples use different small instances; each demonstrates the relevant model and its control.
