\section{Overall Search Architecture}
\label{sec:architecture}
We propose two complete search systems that share the same first stage:
\begin{itemize}
  \item \textbf{Proposal A:} OR-tree for an initial valid timetable (Section~\ref{sec:or}) $\rightarrow$ set-based improvement (Section~\ref{sec:set}).
  \item \textbf{Proposal B:} OR-tree for an initial valid timetable (Section~\ref{sec:or}) $\rightarrow$ AND-tree optimization (Section~\ref{andopt:section}).
\end{itemize}
\[
\boxed{\begin{array}{ccccc}
&&\text{OR-tree feasibility}&&\\[-1pt]
&&\downarrow&&\\[-1pt]
&&a_{\mathrm{init}}&&\\[-1pt]
&\swarrow&&\searrow&\\[-1pt]
\text{Set-based improvement}&&&&\text{AND-tree optimization}\\[-1pt]
\downarrow&&&&\downarrow\\[-1pt]
a_A&&&&a_B
\end{array}}
\]
All three models use the problem definition of Section~\ref{sec:problem}: the components $X$, the domains $D(x)$, the overlap test \eqref{eq:overlap}, the checker $\mathrm{Consistent}$ \eqref{eq:consistent} and $\mathrm{Eval}$.

\textbf{Shared first stage:} Both second stages need a valid timetable to start from. The OR-tree finds one, $a_{\mathrm{init}}$, or exhausts its alternatives. It only looks for feasibility and ignores $\mathrm{Eval}$.

\textbf{How the stages connect:} Both second stages begin with $a_{\mathrm{init}}$ as their best timetable and only replace it with a strictly better valid one, so
\[
\mathrm{Eval}(a_A)\leq\mathrm{Eval}(a_{\mathrm{init}}),\qquad
\mathrm{Eval}(a_B)\leq\mathrm{Eval}(a_{\mathrm{init}}).
\]
