\section{Overall Search Architecture}
\label{sec:architecture}

We propose two search systems that share an initial
OR-tree stage:
\begin{itemize}
  \item \textbf{Proposal A:} OR-tree search finds an initial valid
  timetable, then set-based search improves it through
  moves and swaps.
  \item \textbf{Proposal B:} OR-tree search finds an initial valid
  timetable, then AND-tree search explores alternative
  assignments using branch-and-bound.
\end{itemize}
\[
\boxed{\begin{array}{ccccc}
&&\text{OR-tree finds valid solution}&&\\[-1pt]
&&\downarrow&&\\[-1pt]
&&assign_{\mathrm{0}}&&\\[-1pt]
&\swarrow&&\searrow&\\[-1pt]
\text{Set-based improvement}&&&&\text{AND-tree optimization}\\[-1pt]
\downarrow&&&&\downarrow\\[-1pt]
assign_{A}&&&&assign_{B}
\end{array}}
\]

\paragraph{Time limit.} Both proposals will use a time limit. If it is reached,
the system returns the best complete valid timetable found,
if any, and reports that the search stopped early.
Section~\ref{sec:discussion} explains how this affects
the conclusions we can draw from the result.

\paragraph{Finding a valid timetable.} The shared OR-tree stage constructs a timetable by assigning
components to permitted slots and checking the hard
constraints. It returns the first complete valid timetable,
denoted $\mathit{assign}_0$, without minimizing
$\mathrm{Eval}$.

If every alternative fails, the instance has no valid
timetable. Neither optimization stage begins without
a complete valid timetable.

\paragraph{Improving the timetable.}
Proposal A applies improving moves and swaps to
$\mathit{assign}_0$. Proposal B uses $\mathit{assign}_0$
as its initial best timetable, but searches from the mandatory
assignments so that its other choices remain open.

Both alternatives retain a complete valid timetable and
replace it only when a better one is found. For either
returned timetable
$\mathit{assign}\in\{\mathit{assign}_A,\mathit{assign}_B\}$,
\[
\mathrm{Constr}(\mathit{assign})=\mathsf{true},
\qquad
\mathrm{Eval}(\mathit{assign})
\le\mathrm{Eval}(\mathit{assign}_0).
\]

All models use the domains, constraint checks, and evaluation
function defined in Section~\ref{sec:problem}.
